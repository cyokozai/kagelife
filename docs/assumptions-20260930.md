**プロジェクト**: KageLife
**対象**: LLM が Kage シェーダを操作してリアルタイムコーディング VJ を行う MCP サーバの追加
**前提の出典**: 前提確認ページ「KageLife VJ MCP 前提確認」（2026-09-30）。16 項目すべてを提案どおり Yes で採用し、同日に実装開始の指示を受けた。その後、同日のユーザー判断で #3・#8・#15 を変更した（MCP サーバを別リポジトリ `cyokozai/kagelife-mcp` に分ける。下の「変更の記録」）

## 変更の記録

| 日付 | 対象 | 変更前 | 変更後 | 理由 |
|------|------|-------|-------|------|
| 2026-09-30 | #3 | 同じバイナリの `kagelife mcp` サブコマンドが中継する | 別リポジトリ `cyokozai/kagelife-mcp`（public）の別バイナリ `kagelife-mcp` が中継する | kagelife 本体の依存を ebiten / fsnotify / x/image のまま保てる。MCP 側は cgo も ebiten も要らない純 Go で、クロスビルドと CI が軽い。MCP のプロセスが ebiten を初期化しない（macOS のメインスレッドへの配慮）。公開・リリースの周期を分けられる |
| 2026-09-30 | #8 | go-sdk を kagelife に入れ、依存方針を ADR で更新する | go-sdk は kagelife-mcp だけで使う。kagelife 本体の依存方針は変えない（x/image の記載漏れだけ直す） | #3 の変更に伴う |
| 2026-09-30 | #15 | feat/mcp-stdio-server を kagelife の dev に向ける | feat/mcp-stdio-server を kagelife-mcp の dev に向ける | #3 の変更に伴う |

変更の代償: 配布物が 2 つになる。リポジトリをまたいで契約 v1 を守る必要がある（契約の正典は kagelife の ADR-006 に置き、発見ファイルの `version` で版の食い違いを検出する）。両者を結合した E2E テストはリポジトリをまたぐ。
