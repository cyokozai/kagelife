# ADR-005: クロスフェードと合成 — 画面外合成 + 積算による進行

**ステータス**: Accepted
**日付**: 2026-09-30
**決定者**: cyokozai

---

## コンテキスト

v1.0 に前倒ししたクロスフェード（PRD FR-023〜FR-025）は、Shift+`1`〜`9` で表示中のシェーダー（A）から指定したシェーダー（B）へ、
`[` `]` で選んだ拍数（0.5 / 1 / 2 / 3 / 4 / 8 / 16、既定 4）をかけて移り変わる。長さはタップBPM（PRD FR-030 以降）から求める。

本 ADR を決める前（2026-09-30 時点の dev）の実装には、次の問題があった。

- **B が透けない**: `main.go` は A を画面に描いたあと、`DrawRectShaderOptions.ColorScale.ScaleAlpha(Mix)` を指定して B を同じ画面に `DrawRectShader` で重ねていた。
  しかし `DrawRectShader` では `ColorScale` はシェーダーの `color` 引数に渡るだけで、シェーダーがそれを使わない限り描画に効かなかった。
  同梱のシェーダーはこの引数を使っていないため、Mix を変えても B の透明度は変わらなかった
- **フェード中の再指示の扱いが決まっていない**: `shadermgr.Manager.BeginFade()` はフェード中に呼ばれると B を差し替え、A のまま最初からやり直していた
- **タップ前はフェードが進まない**: `tempo.Tapper.BPM()` はタップが 2 回未満だと 0 を返し、`Manager.Tick()` は BPM が 0 以下だと何もしなかった。
  また、2 秒を超えて空いたタップで履歴が消え、BPM が 0 に戻っていた
- **途中変更で飛ぶ**: `Manager.Tick()` は「フェード開始からの経過時間 ÷（拍数 × 60 / BPM）」で進み具合を求めていたため、フェード中に拍数や BPM が変わると Mix が不連続に変わった

## 決定

### D1: A と B を画面外で合成する

B を画面外の画像（オフスクリーンの `*ebiten.Image`）に描き、その画像を Mix に応じた透明度付きで A の上に重ねる。
画像を重ねる描画（`DrawImage`）では `ColorScale` が透明度として効くため、シェーダー側が `color` 引数を使うかどうかに依存しない。

### D2: フェード中に別のフェードを指示されたとき

| 指示 | 動作 |
|------|------|
| フェード中の B と同じシェーダー | 無視する（フェードを続ける） |
| Mix < 0.5 で、元の A | フェードを取りやめ、A のままにする |
| 上記以外で、Mix ≥ 0.5 | B を確定させて新しい A とし、新しいフェードを始める |
| 上記以外で、Mix < 0.5 | A のままにして、新しいフェードを始める |

### D3: BPM の既定値と制限

- まだタップしていないときは、既定の 120 BPM で拍を刻む
- 前回のタップから 2 秒を超えて空いたタップでも、直前の BPM を保持する
- BPM は 40〜300 に制限する

### 進み具合は積算で求める

Mix は「開始時刻からの経過時間」ではなく、フレームごとの増分（そのフレームの経過時間 ÷ その時点の拍数と BPM から求めたフェードの長さ）を足し合わせて求める。
これにより、フェード中に拍数や BPM を変えても Mix は飛ばず、その時点から新しい速さで進む。

## 理由

- D1: B をいったん画像にしてから重ねれば `ColorScale` が透明度として効き、シェーダーの書き方に依存しない
- D2: 同じ B への再指示を無視すれば、キーの押し直しでフェードが最初に戻らない。Mix 0.5 を境にすれば、そのとき画面で優勢なほうを新しい A として残せる
- D3: タップしなくてもクロスフェードと `Beat` が動き、間を空けて打ち直しても拍が途切れない。BPM は常に 40〜300 の範囲に収まる
- 積算: 拍数・BPM の途中変更で画面が飛ばない

## 影響・結果

**ポジティブ**:
- シェーダーの書き方に関係なくクロスフェードが見える
- 画面外の画像に描いて重ねる経路は、V2 のシェーダーレイヤー合成（最大 9 枚、加算合成とアルファブレンド。[discovery-interview-v2.md](../discovery-interview-v2.md) を参照）への布石になる。レイヤーごとに画面外の画像を持ち、合成方法を切り替える形に広げられる

**ネガティブ**:
- 画面サイズの画像を 1 枚余分に持つ。リサイズや DPI の変化（`LayoutF`）に合わせて作り直す必要がある
- `Manager` の状態（Mix の積算値など）が増え、`Tick()` の引数や呼び方が変わる

**Action Items**:
- [x] D1: B を画面外の画像に描き、透明度付きで重ねる（W1-1、`main.go`）
- [x] D2: フェード中の再指示を上表のとおりに扱い、ユニットテストを書く（W1-3、`internal/shadermgr`）
- [x] D3: 既定 120 BPM・直前の BPM の保持・40〜300 の制限を `internal/tempo` に入れ、ユニットテストを書く（W1-4。測った BPM かどうかを返す `Measured()` も追加）
- [x] 進み具合を積算に変え、拍数・BPM の途中変更で Mix が飛ばないことをユニットテストで確かめる（W1-3、`TickAt`）
- [ ] `Measured()` を HUD に表示する（第 2 波）
